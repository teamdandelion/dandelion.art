# Music offline reference

The personal site stays statically generated. Only music pages opt into Astro's
ClientRouter and the `/music/`-scoped service worker. Home and Art are outside the
offline package and retain ordinary navigation.

The build integration follows dependencies from generated music HTML, including
JavaScript modules, CSS, fonts, and the logo. It adds the app manifest and icons,
hashes the resulting contents and worker source, and writes `/music/sw.js`.
No gallery media is downloaded. Query parameters are preserved in the browser
but ignored when looking up the static music HTML shell in the cache.

Installation precaches the entire reference atomically. A failed installation
removes its partial cache without replacing the active worker. Updates wait until
the user chooses **Update available · reload** (or all old app windows close).
Activation removes only old `dandelion-music-` caches and claims music windows;
open controlled windows reload to avoid mixing versions. Personal storage is not
deleted. Never reuse this prefix for user-generated content.

## iPhone acceptance check

1. Open the deployed music page in Safari. Share → Add to Home Screen.
2. Launch that home-screen app while online; wait for **Available offline**.
   Safari and the installed app may have separate storage.
3. Close the app, enable airplane mode, and launch it again from its icon.
4. Change instrument/key, open a chord not previously viewed, browse voicings,
   open piano, and tap playback. Open the exact shape on the fretboard and edit it.
5. Check Back navigation, theme changes, and a second closed-app launch.
6. Reconnect after a new deployment; confirm the old app remains usable until
   the update is accepted, then confirm the new app still launches offline.

Playwright tests cover fresh-window offline startup, unvisited query URLs,
client navigation without document reloads, Back, piano, update approval, and
failed-download recovery. They do not substitute for the installed iPhone shell.
Browser storage can be cleared or evicted; storage retention isn't guaranteed.
Future songs need separate IndexedDB storage
and export/sync, not the disposable app cache.

Playwright 1.63's WebKit offline-emulation flag has a known navigation bug
([#42775](https://github.com/microsoft/playwright/issues/42775)). The WebKit test
stops its dedicated origin server instead, then reloads and cold-opens uncached
voicing URLs. Chromium additionally exercises the offline-emulation path.

Service workers are generated by the production build, not the dev server.
Use `npm run build && npm run preview` to test locally. HTTPS is required except
on localhost. A preview-domain installation is separate from production.
